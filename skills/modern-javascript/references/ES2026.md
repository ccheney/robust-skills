# ES2026 Features

Array.fromAsync, Error.isError, Math.sumPrecise, Uint8Array base64/hex conversion, Iterator.concat, Map.getOrInsert / getOrInsertComputed (Upsert), JSON.parse source text access.

These all reached TC39 Stage 4 in 2025-early 2026 and are published in ECMAScript 2026. Several (notably `Array.fromAsync` and the JSON.parse source access) shipped in runtimes years before the edition — the edition label reflects spec inclusion, not availability.

## Array.fromAsync()

Create arrays from async iterables (async version of `Array.from`). Long mislabeled as ES2024/ES2025 — it is **ES2026** spec-wise, but Baseline-available since 2024 (Chrome 121, Firefox 115, Safari 16.4, Node 22).

```javascript
// From async generator
async function* fetchPages() {
  yield await fetch('/page/1').then(r => r.json());
  yield await fetch('/page/2').then(r => r.json());
  yield await fetch('/page/3').then(r => r.json());
}

const pages = await Array.fromAsync(fetchPages());
// [page1Data, page2Data, page3Data]

// From any async iterable (e.g. a Node readable stream)
const chunks = await Array.fromAsync(readableStream);

// With mapping function (awaited per element)
const doubled = await Array.fromAsync(
  asyncGenerator(),
  async (x) => x * 2
);

// From sync iterable of promises — each element is awaited
const results = await Array.fromAsync([
  Promise.resolve(1),
  Promise.resolve(2),
  Promise.resolve(3)
]);
// [1, 2, 3]
```

**vs Promise.all — the semantics differ:**

```javascript
// Promise.all: starts ALL work up front, awaits concurrently
const all = await Promise.all(urls.map(u => fetch(u)));

// Array.fromAsync: pulls and awaits ONE element at a time (sequential)
const sequential = await Array.fromAsync(asyncGenerator());
```

Use `Array.fromAsync` to drain an async source in order; use `Promise.all` for concurrency. Don't "optimize" a `Promise.all` into `Array.fromAsync` — you'd serialize the requests.

## Error.isError()

Reliably check if a value is an Error, including across realms (iframes, workers, `node:vm`) where `instanceof Error` gives false negatives.

```javascript
// Problem: instanceof fails across realms
const iframe = document.createElement('iframe');
document.body.appendChild(iframe);
const err = new iframe.contentWindow.Error('oops');

err instanceof Error;      // false (different realm!)
Error.isError(err);        // true ✓

// Works for all native Error subclasses, rejects lookalikes
Error.isError(new TypeError('bad'));      // true
Error.isError(new RangeError('oops'));    // true
Error.isError({ message: 'fake' });       // false
Error.isError(null);                      // false
```

Uses an internal slot check (like `Array.isArray`), so it cannot be fooled by `Object.create(Error.prototype)`. DOMException also reports `true` in browsers.

## Math.sumPrecise()

Sum an iterable of numbers with full precision — avoids the floating-point drift of naive `reduce((a, b) => a + b)`.

```javascript
const values = [1e20, 0.1, -1e20];

values.reduce((a, b) => a + b, 0);  // 0 (0.1 was absorbed and lost)
Math.sumPrecise(values);            // 0.1 ✓

Math.sumPrecise([]);                // -0 (identity of summation)
```

Takes any iterable of Numbers (throws on non-numbers and BigInt). Slower than a plain loop — use it when accuracy matters (finance, statistics, geometry).

## Uint8Array ⇄ Base64 / Hex

Convert bytes to and from base64/hex strings without hand-rolled loops, `btoa` hacks, or Buffer.

```javascript
// Decode
const bytes = Uint8Array.fromBase64('SGVsbG8gV29ybGQ=');
const fromHex = Uint8Array.fromHex('48656c6c6f');

// Encode
bytes.toBase64();                                   // 'SGVsbG8gV29ybGQ='
bytes.toBase64({ alphabet: 'base64url' });          // URL-safe variant
bytes.toHex();                                      // '48656c6c6f20576f726c64'

// Streaming-friendly: write into an existing buffer
const target = new Uint8Array(1024);
const { read, written } = target.setFromBase64('SGVsbG8=');
```

Replaces the `atob`/`btoa` + `charCodeAt` dance (which is Latin-1 only and web-only) and works identically in Node and browsers.

## Iterator.concat()

Sequence several iterables into one lazy iterator (the "Iterator Sequencing" proposal).

```javascript
const first = [1, 2].values();
const second = new Set([3, 4]);

const combined = Iterator.concat(first, second, [5, 6]);
combined.toArray();  // [1, 2, 3, 4, 5, 6]

// Lazy: nothing is pulled until you iterate,
// so it composes with the ES2025 iterator helpers
const firstThreeEven = Iterator.concat(streamA(), streamB())
  .filter(n => n % 2 === 0)
  .take(3)
  .toArray();
```

Prefer it over `[...a, ...b].values()` when the sources are large or infinite — no intermediate array is built.

## Map.getOrInsert() / getOrInsertComputed() (Upsert)

Read a key, inserting a default when absent — one lookup instead of the classic `has`/`get`/`set` triple. Also on `WeakMap`.

```javascript
const wordCounts = new Map();

// ❌ Before
for (const word of words) {
  if (!wordCounts.has(word)) wordCounts.set(word, 0);
  wordCounts.set(word, wordCounts.get(word) + 1);
}
```

```javascript
// ✅ After — grouping accumulator in one line
const index = new Map();
for (const item of items) {
  index.getOrInsert(item.category, []).push(item);
  // returns existing array, or inserts [] and returns it
}

// Lazy default: callback runs only when the key is missing
const cache = new Map();
function expensiveFor(key) {
  return cache.getOrInsertComputed(key, k => computeExpensive(k));
}
```

Use `getOrInsertComputed` when constructing the default is costly; plain `getOrInsert` always evaluates its default argument.

## JSON.parse Source Text Access

The reviver's third argument exposes the raw source of primitive values, and `JSON.rawJSON()` lets you serialize exact numeric text — fixing the classic "big int loses precision through JSON.parse" bug.

```javascript
// Problem: 64-bit ids overflow Number
JSON.parse('{"id": 12345678901234567890}').id;
// 12345678901234567168 (silently corrupted)

// Solution: read the source text in the reviver
const data = JSON.parse('{"id": 12345678901234567890}', (key, value, context) =>
  key === 'id' ? BigInt(context.source) : value
);
data.id;  // 12345678901234567890n ✓

// And write it back without quotes using rawJSON
JSON.stringify({ id: JSON.rawJSON('12345678901234567890') });
// '{"id":12345678901234567890}'

JSON.isRawJSON(JSON.rawJSON('123'));  // true
```

`context.source` is only provided for primitive values (numbers, strings, booleans, null) — for objects/arrays the reviver gets no source.

## Browser/Node.js Support

First versions with unflagged support (source: MDN browser-compat-data, 2026):

| Feature | Chrome | Firefox | Safari | Node.js |
|---------|--------|---------|--------|---------|
| Array.fromAsync | 121+ | 115+ | 16.4+ | 22+ |
| Error.isError | 134+ | 138+ | preview/flag | 24.3+ |
| Math.sumPrecise | 147+ | 137+ | 26.2+ | not yet (flagged) |
| Uint8Array from/toBase64, from/toHex | 140+ | 133+ | 18.2+ | 25+ |
| Iterator.concat | 146+ | 147+ | 26.4+ | 26+ |
| Map.getOrInsert(Computed) | 145+ | 144+ | 26.2+ | 26+ |
| JSON.parse source access / rawJSON | 114+ | 135+ | 18.4+ | 21+ |

Only `Array.fromAsync` and JSON source access are safe on older baselines; treat the rest as **Node 25-26+ / late-2025+ browsers** and feature-detect or polyfill (core-js covers all of them) elsewhere.
